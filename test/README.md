# Fixture suite

A small end-to-end suite for the three tools. Each fixture runs one command on synthetic
data and compares every file it writes against `fixtures/<name>/expected/`.

```sh
python3 test/run_tests.py --impl .            # the Perl scripts in the repository root
python3 test/run_tests.py --impl . --record   # rewrite expected/ from the Perl
```

`--impl` takes any directory holding `reStraining`, `reStrainingOrder` and
`reStrainingReport`, so the same fixtures can check another implementation. The Perl needs
`samtools` in the `PATH`.

## The data

`test/data/` is generated by `make_data.py` from a fixed seed (rerunning it reproduces the
files): a 4 kb chromosome 1 plus chromosomes 2 and MT, MGP v8 and v7 style VCFs for six
strains, the chromosome 1 matrix, and simulated alignments to the N-masked genome:

| File | What it is |
|---|---|
| `pure_CAST.sam` | 400 reads from the CAST_EiJ haplotype |
| `hybrid_DBA_PWK.sam` / `.bam` | 600 reads from DBA_2J and PWK_PhJ, plus one read per branch of the per-read classification (unmapped, soft clip, insertion, one and two deleted Ns, genuine Ns in the reference, mismatches before an N, both alleles in one read, chromosome 2, MD starting with an N) |
| `bs_WSB_SE.sam` | Bismark single-end, all four strands, C>T and G>A conversion |
| `bs_AJ_PE.sam` | Bismark paired-end, mates adjacent |
| `bs_AJ_PE_possorted.sam` | the same pairs with mates apart, so the Perl sorts by name |

The VCFs also carry every record the filter has a rule for: a REF that is not a base, a
two-base REF, two ALTs, a `*` ALT, REFs that disagree with the genome, low-confidence and
heterozygous calls, positions no strain calls with confidence, and (v7) INDELs.

## What is compared, and how

Outputs are compared in both directions, so a file only one side writes is a failure.
`EXIT` is the exit status, `STDOUT` is compared where the fixture has a `stdout` marker,
and `ignore` lists outputs a fixture does not compare.

The Perl iterates hashes in several places, so some outputs change order from run to run.
They are put in a canonical form before comparing:

- **Tied rows** in the strain, hybrid and allele-ratio tables are ordered by name, within
  each run of consecutive rows with the same sort key; the runs stay where they are, so an
  output that is not sorted still fails. Each allele-ratio row moves with its hybrid row,
  since the Perl writes both in the same order.
- **The genome preparation report** has its lines sorted: chromosomes are processed in hash
  order.
- **HTML reports** have the date and time blanked, and each embedded asset line (plotly.js,
  the logos) is replaced by its size and SHA-256. The HTML written at the end of a
  `reStrainingOrder` run is not compared, because its tables come from the summary in
  whatever order ties fell; the `report_*` fixtures check the HTML from a fixed summary.
- **gzip** outputs are compared decompressed. **BAM** files are ignored: the Perl writes them
  as a side effect of calling samtools (SAM to BAM, sort by name).
- **Exit statuses** other than 0 and 1 are recorded as `error`, because Perl's `die` exits
  with whatever `errno` was.

Behaviour the fixtures pin that looks like a bug is kept on purpose, so that the suite
describes what the Perl does today. The notable cases:

- `order_two_files`: SNP counts and strain tallies carry over from one input file to the
  next, so the second file's scores include the first file's reads.
- `order_bisulfite_pe_possorted`: the report is named `bs_AJ_PE_posreStrainingOrder_report.txt`,
  because `sorted.` is removed wherever it appears in the input name.
- `prepare_*`: only chromosome 1 is filtered and N-masked; the other chromosomes are written
  out unchanged.
